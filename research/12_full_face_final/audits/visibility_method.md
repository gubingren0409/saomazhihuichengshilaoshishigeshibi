# Visibility implementation and validity boundary

Author role: `/root/face_visibility`. This is implementation reasoning and author tests, not the independent review or field verification.

The roadmap retains every free-space reflex corner: exterior concavities and obstacle-hole convex corners. Ring orientation is respected. Turns use a floating determinant with exact rational orientation fallback near zero; no nonzero corner is removed by an empirical collinearity tolerance. Polygon vertices are never moved or simplified. Portals and source-required gate points keep their original coordinates and remain unrestricted query/interface vertices even when coincident with a corner.

For uniform Euclidean path length in a fixed closed polygon component, shortest paths bend only at free-space reflex vertices. A bend cannot require an edge that is non-supporting at that corner: both adjacent polygon neighbors on opposite sides of that departure allow shortening the bend locally. The implementation therefore uses local tangent support at corner endpoints before performing expensive whole-segment visibility. Portal/gate endpoints are exempt from that pruning. This reduces graph construction without changing the polygonal shortest-path problem; the synthetic suite also compares the reduced roadmap against its dense visibility form.

Every retained edge is checked as an entire line, including holes. Main APP edges also use `face_geometry.face_edge_conflicts`, combining the exact component, full-source common constraints and the original zero-width barrier/gate policy. Buffer vertices are those of the actual .25m/q16 polygonal domain; there is no new smoothing or curve approximation. R1 removes the earlier `EPS` visibility admission: membership is strictly `covers`, including the synthetic micro-hole rejection.

Positive-area components use independent corner names. Point-touching polygons do not connect in the pure polygon shortest-path helper. In the APP overlay, an already legitimate native source node shared by components retains its source-topology role; new same-coordinate corner names alone do not connect components. Root integration keeps the old graph. Distinct same-endpoint geometric alternatives are retained in `routing_alternatives`; each request uses its own F0/F1 cost function to select the corresponding segments, rather than discarding a longer geometric option that could be cheaper under F1.

Source-interface policy is finite and explicit: all ground/permission-compatible native nodes inside a component, every certified original-native/old-derived/local-grid boundary intersection, and the existing local external interfaces participate. Original source arcs are not removed. Inserted points split complete original polylines into directed equivalent pieces, retaining source IDs, tags, geometry and cost ratios. The old band interior grid is not converted wholesale into quadratic visibility portals. Source and local zero-length aliases only identify coincident points; positive lengths remain measured.

The second bounded implementation diagnostic addresses actual GEOS intersection roundoff: some computed intersection coordinates were about 1e-12–1.6e-10m outside the strict polygon and could not form legal visibility edges. For derived intersections only, R1 finds the nearest tested representable position along the same original parent arc, capped at 1e-8m in both coordinate and parent-parameter displacement. It records the raw intersection, parent IDs, before/after arc positions, displacement and positive-length covered interval witness. Graph portal coordinates must equal the final split-segment endpoints exactly. Beyond-cap contacts and pure point touches without a covered parent interval are rejected. Raw native nodes, start, door, source polygon, .25m clearance and 30m F0 domain are unchanged; this computational roundoff rule is not a geometric snap or evidence of walking permission.

The complexity trigger is an actual northern Omega of1,872 vertices, including1,774 necessary reflex vertices. A one-pass tangent construction considered1,572,651 pairs but needed only2,838 whole-polygon visibility tests; it produced3,892 directed arcs in5.10s and about59.8MB process RSS. This diagnostic had no query, portals or full-source barrier check and is not an APP route/effect measurement. Failed pair memoization was removed because each pair is tested once; no interfaces were culled for memory.

The exact uniform-polygon theorem applies when the complete feasible set is represented by that polygon and specified endpoints. Additional point-gate or zero-width road policies can impose constraints beyond polygon membership: the practical result is the shortest route in the explicitly validated finite graph, not an unconditional continuous optimum over every possible gate/road/interface position. F1 is the mixed-cost graph minimum, not necessarily shortest geometric length. Source/permission/layer completeness and current public walking access remain unverified in the field.
