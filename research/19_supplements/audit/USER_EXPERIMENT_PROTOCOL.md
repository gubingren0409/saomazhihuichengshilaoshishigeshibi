# 给另一台 AI 的完整实验提示词

## 使用说明

你是负责执行本项目补充实验的研究型 AI。你所在的电脑拥有完整的项目源码、原始数据、冻结实验包、运行环境和必要依赖。你的任务不是重新解释项目，也不是替作者修改历史结论，而是严格按照下列实验协议执行补充实验，并生成可审查的结果文件。

本提示词覆盖四类实验：

1. Q2：入口坐标与目标门身份、地图接入关系核验；
2. Q6：OSM/地图数据与算法输出的一致性、现实真值对照；
3. Q7：关门、封路和动态障碍下的容错与备用路线；
4. Q8：大路网、多候选和备选路径的性能测试。

如某个实验需要现场数据、实时状态或缺失的源码，不得伪造结果。必须将该实验标记为 `BLOCKED_BY_MISSING_INPUT`，列出缺失输入，并完成不依赖该输入的部分。

不得修改历史实验结果、历史源文件、冻结指标、原始地图对象或已有结论。所有新增实验必须使用新的实验 ID、新的输出目录和新的运行记录。

## 一、全局执行规则

### 1. 实验身份

为每个实验生成唯一 ID：

- `Q2-LOCAL-ENTRY-AUDIT-R1`
- `Q6-LOCAL-MAP-CONSISTENCY-R1`
- `Q6-FIELD-TRUTH-COMPARISON-R1`
- `Q7-DYNAMIC-CLOSURE-SIMULATION-R1`
- `Q8-SCALE-LATENCY-BENCHMARK-R1`

实验开始前记录：

- 当前代码 commit 或版本号；
- 输入数据版本、SHA256 或 manifest 身份；
- Python/Node/数据库/空间库版本；
- 操作系统和硬件信息；
- 是否使用缓存；
- 是否访问网络或外部 API；
- 当前时间，统一使用 ISO 8601 格式和明确时区。

### 2. 版本和数据纪律

- 只读使用历史冻结数据；新增数据另存，不覆盖原文件。
- 不修改历史报告中的数字和状态。
- 不把实验重跑结果写回 `HANDOFF_PACKAGE` 原始文件。
- 不把同一建筑的多个裁片自动当成多个独立建筑。
- 不把重复对象、重复路线或回放结果计为新的独立样本。
- 不把 HTTP 200、图上存在、路线可求解或候选点可达解释成现实入口真实存在。
- 不将 F0/F1 条件路线写成现场可通行路线。
- 不将 `main` 或 `exit` 标签自动解释为当前公众开放状态。

### 3. 每次运行必须保存

每个实验至少保存以下文件：

```text
experiment_id/
  README.md
  protocol.json
  environment.json
  input_manifest.csv
  raw_results.jsonl
  summary.csv
  summary.json
  failures.csv
  provenance.csv
  logs/
  figures/
```

每个结果行至少包含：

- `experiment_id`
- `run_id`
- `scene_id`
- `building_id`
- `entrance_id`
- `method`
- `input_version`
- `status`
- `result`
- `failure_reason`
- `route_length_m`
- `assumption_length_m`
- `runtime_ms`
- `source_edge_count`
- `derived_edge_count`
- `assumption_edge_count`
- `output_file`

### 4. 结果状态枚举

只能使用下列状态，不能自行发明含义相近的状态：

- `PASS`
- `FAIL`
- `NO_PATH`
- `INVALID_INPUT`
- `NOT_APPLICABLE`
- `BLOCKED_BY_MISSING_INPUT`
- `INCONCLUSIVE`
- `RUNTIME_ERROR`

### 5. 报告规则

实验报告必须分开写：

1. 观察到的事实；
2. 算法输出；
3. 与基线相比的变化；
4. 允许得出的结论；
5. 不允许得出的结论；
6. 失败和未知原因。

不得写“证明真实可走”“证明公众一定能进”“证明 OSM 正确”等超出实验设计的结论。

## 二、实验 Q2：入口坐标、门身份和接入关系核验

### 可直接复制给执行 AI 的提示词

```text
你现在执行实验 Q2-LOCAL-ENTRY-AUDIT-R1。

实验目标：
在不进行现场调查的前提下，核验项目中的登记入口坐标、建筑身份、门用途、地图上下文和末段接入关系是否在数据内部一致；同时判断“即使入口坐标正确，补全入口接入是否仍有独立意义”。

注意：本实验只能验证地图和数据内部一致性，不能验证现场门是否存在、是否开放、是否允许公众进入。不得把本实验结果写成现场真值。

输入要求：
1. 读取目标建筑对象、登记入口/出口对象、道路对象、原生步道、步行面、障碍、围栏、private 区域和路线结果。
2. 优先使用冻结的 PG1_MAP_CONTEXT_RECONSTRUCTION_R2 数据和最新合法版本。
3. 至少包含以下三个场景：
   - 上海博物馆南门 main；
   - 上海博物馆北侧 exit；
   - 一个有登记门的图书馆场景。
4. 如果图书馆没有合格登记门，必须保留该场景并标记为 INVALID_INPUT，不得用代理点冒充真实入口。

实验 A：对象身份核验
1. 对每个场景确认建筑对象 ID、入口对象 ID、入口标签、入口用途、经纬度和源文件来源。
2. 检查入口是否落在目标建筑边界内、边界上、边界外或无法判断。
3. 检查入口与最近道路、最近原生步道、最近合法步行面的距离。
4. 检查入口附近是否存在围栏、障碍、private 面、水体、建筑内部区域或其他禁止对象。
5. 检查旧地图窗口与最新地图窗口是否绑定同一目标建筑；如果不一致，记录为场景绑定错误，不修改历史结果。

实验 B：目标替代对照
对每个有效入口分别运行以下三个目标定义：
1. 登记入口坐标；
2. 目标建筑中心点；
3. 入口外侧接近点/算法原始接近点。

对每种目标定义使用完全相同的起点、地图版本、障碍、权限、求解器版本和成本参数。记录：
- 是否有路线；
- 路线长度；
- 原生段长度；
- 面派生段长度；
- F0/F1 假设段长度；
- 是否穿越建筑、围栏、private 或障碍；
- 终点到登记入口的距离；
- 求解时间；
- 失败原因。

实验 C：接入价值判定
1. 比较“仅到建筑中心点”和“到登记入口外侧”的路线。
2. 判断登记入口目标是否导致额外末段接入、不同路线或不同失败原因。
3. 如果入口坐标内部一致但接入路线仍出现缺口，记录为 SUPPORTS_ACCESS_COMPLETION。
4. 如果入口对象与建筑身份不一致，记录为 INVALID_ENTRANCE_IDENTITY。
5. 如果两者路线完全一致，不能写“接入补全无意义”；只能写“在该场景和该起点下未观察到额外业务收益”。

输出：
1. entry_identity_audit.csv：每个入口一行，包含建筑、入口、用途、坐标、边界关系、道路距离、步道距离、障碍关系和身份结论。
2. target_definition_comparison.csv：每个场景×目标定义一行，包含路线状态、长度、分段来源、假设段和失败原因。
3. entry_access_figures/：至少生成目标建筑、入口、道路、步行面、障碍和路线叠加图。
4. README.md：分别写“地图内部确认”“未能确认的现场事实”“允许的结论”“不允许的结论”。

判定标准：
- 坐标与建筑/门身份一致，不等于现场门真实存在；
- 登记坐标正确但到门外需要额外连接，支持补全接入有独立价值；
- 目标点不同造成路线或失败状态变化，说明终点定义影响末段规划；
- 出现穿建筑、穿围栏或穿 private 的路线，必须判为 FAIL，不得只报告路线长度；
- 任何现场开放状态未知都必须保留 UNKNOWN。
```

## 三、实验 Q6A：OSM 和算法内部一致性

### 可直接复制给执行 AI 的提示词

```text
你现在执行实验 Q6-LOCAL-MAP-CONSISTENCY-R1。

实验目标：
验证 OSM/冻结地图数据在进入算法后，是否被正确读取、过滤、建图、连接和用于路线；区分源对象发现、图准入、图内可达和业务路线使用。不要把本实验解释成现实现场真值验证。

输入要求：
1. 使用项目冻结的 OSM 场景和对应 source index。
2. 至少覆盖 WALKABILITY-R2、WALKABILITY-R3、FREE-SPACE-R1-FINAL、PEDESTRIAN-AREA-SHORTEST-R1-FINAL-FIXED、PED-AREA-CONNECTIVITY-R1/R2 的固定输入。
3. 读取原生 node/way/relation、步行面、障碍、建筑、围栏、private 面、路线边序列和已有指标。
4. 每个场景必须保留原始对象 ID，不允许仅依赖渲染图片判断对象存在。

实验 A：源对象到图的追踪
对每个源对象记录：
1. 是否被发现；
2. 是否被解析；
3. 是否通过准入；
4. 被拒绝的原因；
5. 是否生成原生边；
6. 是否生成面派生边；
7. 是否生成条件假设边；
8. 是否出现在最终业务路线中。

实验 B：草地误过滤复核
1. 读取 WALKABILITY-R2 的修复前后输入。
2. 对齐恢复的 377 条原生片段和 754 条有向弧。
3. 检查每条恢复片段的源 ID、方向、层级和几何是否来自原生对象。
4. 检查恢复后是否误把整片草地当成自由可走空间。
5. 将结果标记为 RESTORED_NATIVE_EDGE、UNSUPPORTED_DERIVED_EDGE 或 REJECTED_EDGE。

实验 C：新增 82 个步行面复核
1. 对 PED-AREA-CONNECTIVITY-R1/R2 中 82 个新增唯一面逐一追踪。
2. 判断每个面是否在业务面池内、是否通过准入、属于哪个有向分量、是否有 owner。
3. 检查它是否进入任何最终业务路线。
4. 对路线未使用的面给出原因：池外、代价更高、其他分量、无 owner、无合法接口或其他明确原因。

实验 D：路线约束审查
对所有固定路线检查：
1. 是否穿过建筑内部；
2. 是否穿过 private 区域；
3. 是否穿越围栏、障碍或水体；
4. 是否使用未声明的假设边；
5. 是否把道路轴当作原生人行道；
6. 是否把二维相交错误解释成同层连通。

实验 E：保存结果重现
1. 对已有保存路线重新计算路线长度、边数量、原生/派生/假设段长度。
2. 将重算值与原始 CSV/JSON 对齐。
3. 对浮点数使用项目原先规定的容差；不得为了通过测试任意放宽阈值。
4. 对不能重现的结果记录输入版本、代码版本、随机性、缓存和误差来源。

输出：
1. source_to_graph_trace.csv；
2. restored_native_edges.csv；
3. added_face_usage.csv；
4. route_constraint_audit.csv；
5. replay_comparison.csv；
6. summary.json；
7. 至少生成四类图：源对象、准入结果、图分量、最终路线叠加图。

判定标准：
- 源对象存在但未准入，不算算法漏读；必须记录拒绝原因；
- 对象进入图但未进入路线，不算业务收益；
- 发现穿障碍、穿建筑或未声明假设段，判为 FAIL；
- 保存结果与重算结果不一致时，先检查版本和输入，不得直接修改历史数字；
- 本实验只能支持“算法对冻结地图的处理是否一致”，不能支持“地图与现实是否一致”。
```

## 四、实验 Q6B：OSM 与现实现场真值对照

### 可直接复制给执行 AI 的提示词

```text
你现在执行实验 Q6-FIELD-TRUTH-COMPARISON-R1。

实验目标：
比较冻结 OSM/算法路线与独立现场观察，量化哪些路段是真实可走、哪些是地图缺失、哪些是算法误连、哪些是动态现场状态。该实验需要现场调查或由独立人员提供带时间戳的现场记录。

禁止事项：
1. 不得用地图截图代替现场真值；
2. 不得由开发算法作者单独给自己的路线打“真实可走”标签；
3. 不得把一次现场观察推广成永久事实；
4. 不得把 F0/F1 命中写成一般性真实性证明。

样本：
1. 选择 3 个建筑，每个建筑选择 2 个门外目标，共 6 条路线。
2. 至少包含一条原生线主导路线、一条合法步行面主导路线、一条包含 F0/F1 假设段的路线。
3. 现场调查时间必须记录，最好在同一日期完成全部路线。

步骤：
1. 在调查前冻结地图、代码、入口列表、路线请求和输出。
2. 由独立调查人员实地走每条路线。
3. 将每条路线拆成与算法边对应的路段。
4. 对每段记录：存在/不存在、可通行/不可通行、是否同层、是否开放、是否有临时障碍、是否需要绕行、观察时间和证据照片/轨迹。
5. 将现场记录与算法的原生段、面派生段、条件假设段逐段对齐。
6. 计算现实可走比例、假阳性、漏报、距离误差和假设段命中率。

输出：
- field_truth_segment_labels.csv；
- algorithm_field_confusion_matrix.csv；
- route_level_comparison.csv；
- field_photos_or_tracks/；
- field_protocol.md；
- final_report.md。

判定标准：
- 原生段现场存在且可走：支持原生地图段；
- 面派生段现场可走：支持该类面内计算在该案例中的现实合理性；
- F0/F1 段现场可走：只支持该案例，不外推到所有缺标空间；
- 算法可达但现场不可走：假阳性；
- 现场可走但算法不可达：漏报，进一步检查缺标或过严准入；
- 现场状态不稳定：标记为 DYNAMIC_OR_TIME_DEPENDENT，不并入静态真值。
```

## 五、实验 Q7：关门、封路和动态障碍模拟

### 可直接复制给执行 AI 的提示词

```text
你现在执行实验 Q7-DYNAMIC-CLOSURE-SIMULATION-R1。

实验目标：
在本地构造可重复的入口关闭、步道封闭和临时障碍场景，检查系统是否会重新求路、避免使用失效边、返回备用路线或正确报告 NO_PATH。该实验验证的是算法对状态变化的容错，不验证系统是否能自动感知现实变化。

基线：
1. 选择两个有至少两个接近方向或候选入口的固定场景；
2. 冻结一条主路线和一条可能的备用路线；
3. 保存正常状态下的路线、边序列、长度和求解时间。

构造五种状态：
S0：正常状态；
S1：关闭主入口；
S2：删除主路线中的一条原生步道边；
S3：在主路线附近加入临时障碍多边形；
S4：同时关闭主入口并封闭主路线一段；
S5：恢复所有对象到正常状态。

执行步骤：
1. 对 S0 求解并保存完整路线。
2. 对 S1–S4 分别提交完全相同的请求，只改变关闭/障碍状态。
3. 检查输出路线是否仍包含关闭入口、删除边或穿越障碍。
4. 如果有备用路线，记录备用路线长度、增加的假设段和求解时间。
5. 如果没有备用路线，检查系统是否返回 NO_PATH 或需人工确认，而不是返回旧路线。
6. 对 S5 重新求解，检查原路线是否可以恢复。
7. 每种状态至少重复 3 次；记录冷启动和热启动时间。

必须保存：
- dynamic_scenarios.json；
- closure_edge_changes.csv；
- dynamic_route_results.jsonl；
- forbidden_object_usage.csv；
- fallback_route_comparison.csv；
- state_transition_figure.svg 或 png；
- runtime_log.csv。

判定标准：
- 关闭入口后路线不得把该入口当作可用目标；
- 删除边后路线不得继续使用该边；
- 临时障碍与路线相交时必须重新规划或失败；
- 存在合法备用路线时应返回备用路线；
- 不存在备用路线时应明确失败；
- 不得从缓存返回已失效路线；
- 恢复状态后路线应与 S0 一致或给出可解释差异。

报告限制：
明确写出本实验没有测试实时状态感知、真实施工、真实人流、真实 GPS 或实际门禁系统。
```

## 六、实验 Q8：大路网、多候选和备选路径性能

### 可直接复制给执行 AI 的提示词

```text
你现在执行实验 Q8-SCALE-LATENCY-BENCHMARK-R1。

实验目标：
测量当前系统在不同路网规模、候选入口数量、路线数量和图模式下的运行时间，判断是否满足“一秒返回”的要求。必须区分冷启动、热启动、图构建、单次求路和完整请求端到端时间。

不得做的事：
1. 不得只报告平均时间；
2. 不得把单个小场景成功求路写成大路网实时性能；
3. 不得把缓存命中结果和冷启动结果混在一起；
4. 不得用旧路线回放代替真实求解；
5. 不得为了达到一秒目标而删掉必要约束、障碍检查或候选入口。

测试规模：
1. 小规模：现有冻结开发场景；
2. 中规模：合并多个相邻冻结裁片，保留对象 ID 和空间边界；
3. 大规模：使用可合法使用的城市级或更大路网数据；如果没有大规模数据，必须标记 LARGE_NETWORK_NOT_AVAILABLE，不得伪造。

候选数量：
- 1 个候选入口；
- 10 个候选入口；
- 100 个候选入口；
- 如果数据不足，使用实际可用上限并记录原因。

查询类型：
1. 单条最短路线；
2. Top-3 备选路线；
3. F0；
4. F1；
5. EDGE_BAND；
6. FULL_FACE；
7. 删除一条边后的重新规划；
8. 多候选入口联合选择。

执行要求：
1. 每种配置至少运行 30 次；如果构图极慢，至少运行 10 次并解释原因。
2. 前 3 次作为 warm-up，不能进入正式统计。

6. 每次运行保存代码版本、输入 manifest、随机种子、缓存状态和硬件信息。

一秒目标：
必须提前声明计时口径。默认同时报告：
- 热启动单次求路是否 ≤ 1000ms；
- 冷启动端到端请求是否 ≤ 1000ms；
- p95 是否 ≤ 1000ms；
- 最慢请求是否 ≤ 1000ms。

性能结论规则：
- 只有 p95 和最慢请求都达到 1000ms，才能报告“在该测试配置下满足一秒要求”；
- 只有小规模达到要求，必须写“仅小规模达到要求”；
- 中/大规模没有测试，写 NOT_TESTED；
- 任一关键配置 p95 超过1000ms，不能宣称系统总体一秒返回；
- 如果批量构图比基线更慢，必须报告差值，不能只报告最终路线成功。
```
