# R3 独立实物核查

审查执行者为 Codex 子代理 `r3_contract`。本代理编写共同表示与适配器，独立于本地路由运行、托管请求、路线对照图及打包实现。下述审核不包含本代理自己的适配器独立复核。适配器另有契约自动测试和实际输入回放。

## 已核查

- 重新读取五个冻结 OSM 裁片，核验 SHA256、版本、bounds、建筑原生 ID、起点原生节点及唯一选中的 OSM 标签入口。其余四个请求目标为代理位置。每栋楼的场景仍在冻结分母中。
- 比较本地请求、35 m 冻结 snap 限值与保留路线产物。逐段核对四条返回路线的原生 way 和 node、边界点、连续性、显式步行方向及长度。原生证据包含共享街道假设、道路轴线和源图中的专用步行段。新世界城保存的结果是 `NO_DIRECTED_PATH_BETWEEN_NEAREST_SNAPS`，没有被写成有路线。
- 核对 25 次托管请求均为实发 HTTP 200，每栋最多 5 次。五条路线均能以原始响应第一条要素的顶点重建。请求端点与冻结点一致至 1 mm。20 个静态请求的参数与冻结 bounds、分辨率、地图样式及默认署名一致。实际相机估计和对齐核验保留在托管运行记录中。
- 用独立 GeographicLib 重算九条返回路线的 WGS84 椭球长度和两端偏差。上海图书馆的本地和托管终点距 OSM 标签入口分别为 0 m 和约 0.03 m。其他四个场景的托管折线末点距代理目标约 6.73、22.25、8.42 和 19.78 m。五份托管原始响应中的 waypoint 接近请求坐标，留存响应均无明确内部 snap 字段。
- 解码并检查新场景的 20 张本地 PNG、20 张托管 PNG，全部尺寸及 SHA256 与留存记录相符。本次检查只覆盖工程产物、请求几何与路由文件，视觉偏好留给用户填写。

逐场景结果、路段证据计数和可重跑代码见 [复核记录](independent_r3_receipts.json) 与 [复核脚本](independent_r3_receipts.py)。

## 边界

本轮无实地通行验证。来源数据共享 OSM，托管内部图、快照、道路开放和入口实际可用性未知。复核验证了保留实物之间的追溯关系与几何一致性。新世界城差异和其他场景的长度变化仍不能单独归因于引擎、数据更新或内部权重。视觉评判仍为 `PENDING_USER_REVIEW`。独立解包和浏览器回放另写在固定包外，避免改变封存 ZIP。
