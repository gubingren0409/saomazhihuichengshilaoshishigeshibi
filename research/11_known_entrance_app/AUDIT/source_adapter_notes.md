## 实际输入

六个原冻结 OSM JSON 已逐个比对 R4 的 `snapshot_sha256`，原字节复制到 `data/scenes/{scene_id}/source.osm.json`。未下载新地图，未请求 API。坐标事实为 OSM WGS84，经 pyproj 从 EPSG:4326 实际转换到 EPSG:32651，距离为米。

R4-REV1 的原始逐边证据文件 SHA256 和代码来源记录在 `source_staging.json`。按场景流式保留原行，压缩到 `mapped_edges.jsonl.gz`，没有从历史路线文件提取边。博物馆98,102行，新世界47,732行，图书馆5,435行，上海中心3,957行；另外两场景无已有面派生边。每行原有 `parent_input_sha256` 与原场景源一致。3米边缘带、0.5米网格、0.25米净空沿用原 R4-REV1，未开放整片广场。

## 统一限制与图

`restricted` 使用 foot 特定权限优先于一般 access，锁闭与条件权限仍受限。所有场景按统一闭合面语义解析 private 停车/用地/建筑等区域，不按任务名或对象 ID 放行。原关闭道路环本身不自动变成权限面；需要明确面语义。未能解析的潜在危险不得当作空白安全空间。

APP 允许读取全部冻结源；BENCHMARK 仅由可信导出步骤取得独立负向面，导出没有原节点/关系成员数组、隐藏步道、正向步行面或边界放行线。不按隐藏参考形状裁切，固定观察窗口仅选择完整对象；源 ID 被禁止时整对象排除。完整图、权限及当前路线应由主内核统一检查，数据准备本身不是最终路线通过证明。

原生图使用冻结 S1 语义逐段检查；有效原生步道不因草地背景消失。首轮六场景实际源准备复算得到跨裁片去重377段，保存在 `source_preparation.json`（执行版本时间见 `source_code_freeze.json`）。共同约束额外检查之后的实际图和路径以当前求解运行记录为准，不能只凭此377宣称路线正确。

源图保留层级键，二维相交不补连通。平行源边的全部候选记录在 `alternative_segments`，应在共同限制过滤后选择合法最小代价，避免先取最短而丢合法替代。原生、已标面派生和 F0 假设段身份分开。

APP 局部观测域是原门心160米，预测自由域原门心30米，前段使用冻结裁片内完整可用源图。完整前段必须核查完整源限制，不能拿门心30米限制替代整路线检查。现有车行线按冻结政策保留；零宽中心线不等于精确车道边界，缺失宽度和现实障碍仍未知。

## 工程边界

运行所需原源、面边及最小源码已随新工程保存，不需要旧用户 Windows 绝对路径。`source_staging.json` 中绝对路径仅是历史来源指纹。无凭据、无外部网络、无模型或参考答案缓存。

`scripts/prepare_scenes.py` 可从这些已交付实物重新执行来源准备，不产生路线；真正路线须通过同一后端求解器。测试、作者准备、独立审核、用户验收和现场验证分开记录。
