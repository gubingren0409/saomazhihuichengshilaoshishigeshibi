# 上海博物馆路线差异诊断

首轮盲评侧 **A＝Geoapify，B＝本地 OSM**。源身份按首轮随机图册及本机映射核验，本文用来源名，避免把输入说明中的示意顺序误用为实测编号。

## 起点附近

- **OBSERVED / RECOMPUTED** 两条路线都从冻结起点 node/476682043 对应的 way/39764601 开始。本地起点偏差为 0，托管折线起点偏差约 0.036 米。两条线沿同一人行道约 44.16 米，在 node/13763096985 分开。
- **RECOMPUTED** 本地从 way/39764359（`highway=footway`、`footway=sidewalk`）开始，走 165953415、39764607、513764740 等方式绕上海大剧院 way/39763758 北侧。托管折线先沿共有步道再走约 8.6 米，几何随后与黄陂北路 way/654297629、way/1074409256 对应。三个位置的贴线误差约 0.02–0.04 米，属于几何比对，托管原生图边未知。
- **OBSERVED / RECOMPUTED** 两条黄陂北路轴线均标 `highway=tertiary`、`cycleway=lane`，没有可让本地保守 profile 纳入这类车行中心线的 `foot` 或 `sidewalk` 标记。该 profile 下，共有步道延伸的 node/476682036 只连回分歧点。这解释本地图为何不能沿托管折线对应的捷径走。它没有证明现实不能通过黄陂北路。
- **RECOMPUTED** 两条路线在 node/7113798201 附近汇合，随后均使用人民大道过街 way/761403176 对应几何。该过街线通过 node/7113798199、node/7113798198 与两幅道路中心线相接。本地有源 ID 记录，托管侧来自折线几何。分歧到汇合的本地诊断线约 537.35 米，托管约 73.90 米。两条全线另有局部差别，不能用这一区间的差值代替全程差值。
- **RECOMPUTED** 用托管返回的起末坐标在同一冻结本地图内重放接近诊断，仍从相同首边绕大剧院，长度仅变化约 0.009 米。两条源折线的起点、终点坐标也已接近重合。因此仅改变 snap 位置无法解释本地分歧。将两种引擎放在同一张图上的反事实因托管图不可用而为 **UNKNOWN**。

## 南侧广场

**OBSERVED** 广场是 OSM relation/2385771（`type=multipolygon`、`area=yes`、`highway=pedestrian`），外环 way/178721643，内环草地区域 way/178721634 和 way/178721647。它与更广的人民广场 relation/2153738 是不同对象。

**RECOMPUTED** 三个可由冻结起点到达的路网接点分别是：

| 边界节点 | 源线 | 含义 |
| --- | --- | --- |
| node/1890745480 | way/761403177 | 过街线在广场边界接入 |
| node/1890935415 | way/178737608 | 人行道在边界接入 |
| node/1890935454 | way/178737605 | 人行道在边界接入 |

在冻结图中，扣除 0.25 米边界带后，穿入广场内部的合格线段数为 **0**。入口参考 node/6897141353 与建筑和广场外环共享原生节点，但该节点没有本地合格步行边。R1 的预处理使用线网，面积对象不转换为广场内部路线。因此，边界接点可达和广场内部可以规划是两个不同的检查结果。当前只确认前者。托管服务是否建了广场内部网以及现实通行均为 **UNKNOWN**。 [图 03 南侧广场](figures/figure03_plaza.png) · [广场审计表](plaza_connectivity_audit.csv)

**OBSERVED / RECOMPUTED** 南侧参考是馆舍轮廓 way/161090899 上的 `entrance=main` 源节点，与广场外环共享。馆方来源指示南门，精确物理位置和当前可进入性未经现场核验。入口身份在数据层是建筑入口参考，不是 POI 中心或路由折线终点。北西侧另有 node/6897145227 标 `entrance=exit`，是否为当前公众入口未知。 [首轮记录的馆方到访说明](https://www.shanghaimuseum.cn/mu/frontend/pg/service/visit-west)

**RECOMPUTED** 本地最近合格线为 way/178719573，最近点是其原生节点 node/1890732610，冻结的吸附上限为 35 米，原入口请求返回 `TARGET_SNAP_OUTSIDE_LIMIT`。托管结果也终止在几乎同一位置，支持“两条结果落到同一邻近路网位置”的解释，但其内部吸附策略未知。直线测距约 50.46 米进入馆舍轮廓，不能当步行通道。托管旧回执的 55.135 米用球面算法，本文统一采用 WGS84 椭球得到 54.986 米。 [图 04 末端缺口](figures/figure04_endpoint.png) · [端点审计表](endpoint_gap_audit.csv)

## 差异可归因到哪一层

| 层 | 可支持的判断 | 边界 |
| --- | --- | --- |
| 源数据 | 本地日期版上海 OSM 快照时点 2026-11-08T21:21:00Z。广场面、入口点、外围线及属性可追溯。 | 托管底图和路由快照具体时点、边 ID、交通限制与图索引未知。两边共享 OSM 地理来源。 |
| 图构建与过滤 | 本地 NetworkX 3.6.1 Dijkstra，`OSM_PEDESTRIAN_CONSERVATIVE_V1`。同一原生图的有向边按米计，黄陂北路轴线不入图，广场内部不建面边。 | 无法确定托管是否使用同版本数据、并行人行图边、不同访问规则或其他扩展。 |
| 请求与路由引擎 | 两边固定 WGS84 经纬度相同。托管请求 `mode=walk`、`type=balanced`、`units=metric`、`format=geojson`，无 avoid 参数。本地方案不把偏好评分作为边权。 | 托管精确惩罚、权重、内部引擎构建与 snap 决策不可由 HTTP 200 反推。 |
| 渲染 | 原近景与上下文分别约 0.51109、2.04436 米/像素，双侧 1200×900，首轮控制点核验视野差小于 1 像素。 | 同尺度控制减少了视觉比较的构图差别。地图色块、标签与道路显隐不能为路线增加图边。 |
| 入口 | 南侧源点在正确的对象边界，缺口对应到明确的路网末点。 | 没有足够证据确认实体门坐标、开放性或可绕建筑通往该门的真实路径。 |

本轮未发新 API 请求，未改算法、阈值、入口或快照。独立核验使用 GeographicLib 和从原生 OSM 重建的邻接关系，见 [独立审核](audits/independent_review.md)。
